# Implementation Plan: generalisation beyond the ten held-out tracks

**Feature**: `011-generalisation-beyond-ten` | **Spec**: `spec.md` | **Research**: `research.md`
**Created**: 2026-09-02

## Shape of the work

Four phases, and the ordering between them is not a preference. Two of the four exist because
`research.md` found a defect rather than because the spec asked for a step.

1. **Make the label trustworthy** (R4). Before any sweep, the run record must derive what policy
   drove from the policy that actually drove. Running first and labelling afterwards is how feature
   009 produced 60 traces stamped with the wrong run.
2. **Generate the third seed set** (R1, R5). Python side, then the Unity side that can read it.
3. **Run the sweep once** (R3). The scene has to be reset first, and the reset has to be verified
   from the output rather than from the Inspector.
4. **Report against the interval, not the percentage** (R6, R7), and write the outcome wherever it
   contradicts something already written.

## Four orderings this feature must not violate

1. **The derived run label before the sweep.** R4: the controller column is a hand-typed string
   whose own tooltip says nothing checks it. A sweep run before that is fixed produces rows that
   cannot prove which policy drove, and SC-003 asks for exactly that proof. Fixing it afterwards
   cannot relabel runs that already happened.
2. **The seed set generated and committed before the sweep, and never touched after.** The whole
   value of this set is that it was looked at once. Regenerating it after seeing a bad result, under
   any justification, destroys the only property that makes it worth running.
3. **The scene reset verified from the run record, not from the Inspector.** R3 measured the scene
   holding seed 13's model with deterministic inference off. Checking a field by eye and then
   running is what produced that state in the first place.
4. **The interval computed and the reading pre-registered before the numbers exist.** R7 fixes what
   each outcome means. Choosing the reading after seeing the result is the failure mode this whole
   project has been avoiding since M3's first negative.

## Technical decisions

### The run label is derived, and the typed field becomes a cross-check rather than the source

`DrivingAgent` reads `BehaviorParameters` already, for the observation-size assertion. It gains a
label built from the model asset actually loaded and the inference mode actually in effect. The
serialised `runId` stays, demoted: when it is set and disagrees with what was derived, the agent
logs an error naming both. A field nobody can contradict is not a check.

**The derived label is what goes in the run record.** Not the typed one, and not a concatenation of
both, because a row has one controller column and a reader must not have to know which half to
trust.

### The third seed set lives in the existing split file

`SeedSplitFile` gains a `generalisation` field and `SeedSet` gains a matching enum value, per R5.
Not a second file: the hardcoded path in `LoadSeeds` is deliberate and its comment explains why.

The Python side gains `GENERALISATION_SEEDS = range(2001, 2041)` and a batch name that produces it,
so the set is generated by the same code path under the same acceptance bound (FR-002).

### The interval is Wilson, and it is a tested function

R6 worked the numbers: the normal approximation reports `[1.00, 1.00]` on a perfect run, which
claims certainty from a finite sample. The Wilson score interval goes in `python/eda/`, beside the
hypothesis tests it will be reported next to, with tests that pin the three rows in R6's table.

### The report reads committed inputs

FR-010, matching M5's SC-006. The evaluation CSV is small and is committed the way the other
evaluation CSVs already are. Raw traces stay out.

## What could make this feature worthless, and the guard for each

| risk | guard |
|---|---|
| the sweep runs with the wrong model or inference mode | the derived label makes it visible in the output rather than in the Inspector; ordering 3 |
| the seed set gets regenerated after a disappointing result | ordering 2, and the set is committed before the sweep runs, so a regeneration is a visible diff |
| a near-perfect result is read as proof | R6 and FR-008: the interval is reported and the reading is pre-registered in R7 |
| the result is read as re-earning or revising M3 | spec's Out of Scope, and SC-005 forbids editing M3's verdict |
| the new tracks are harder for a reason unrelated to learning | FR-002 and the pooled steering-demand bound, the same one both existing splits were held to |
